# 研发流程与模型分工讨论

> 来源：ChatGPT 对话「DAEN 域联」。这是讨论记录与待验证建议，不是已经生效的研发规范。

## 用户提供的成本背景

- 主要开发工具：Trae、DeepSeek。
- Trae 为固定月费包月；DeepSeek 按量充值。
- 用户认为多用 Trae 可能降低边际成本。

这些是对话当时用户提供的信息；费用、套餐和产品能力可能变化，正式估算时应重新核实。

## 助手提出的路由建议（未确认）

| 任务类型 | 建议工具/角色 | 说明 |
|---|---|---|
| 高频常规开发、UI、普通 Bug | Trae | 利用固定月费；不能只看 token 边际成本，还要计入人工盯工与返工 |
| 输入明确、批量生成 | DeepSeek | 如 SQL、DTO、测试样例、脚本和文档；限制反复探索以控制按量消耗 |
| 复杂工程问题 | 先常规处理，失败达到阈值后升级 Codex | 对话建议阈值为 Trae 两次失败，尚未基于项目数据验证 |
| 架构、复杂评审、最终 Review | Claude | 对话中的角色建议，不是已配置或已批准的团队安排 |

对话里还出现过 GPT 做产品讨论、Claude 做架构/Review、Trae 主力开发、DeepSeek 批量任务、Codex 处理复杂问题的角色划分。这些角色仅供评估，避免将角色名称与特定模型永久绑定。

## 建议的 M1 流程验证

对话建议以 **DAEN / Geo Core M1** 作为 NiuMa 研发流程的第一条完整验证案例。建议流程如下，具体内容需由项目范围和用户确认后再执行：

1. 提交需求输入。
2. 生成 Scope、Non-scope、验收标准和风险。
3. 人工确认需求基线。
4. 进行技术设计与任务拆分。
5. 按任务性质分派，记录工具、成本和返工。
6. 执行构建、测试和 Review；失败后返工并记录原因。
7. 人工验收交付物，形成阶段总结。

对话提出的观察指标：需求理解准确度、任务拆分质量、人工干预次数、测试/返工结果、最终交付质量。应补充可操作的评分口径与基线，否则这些指标无法比较。

## 成本判断口径建议

助手提出用“AI 费用 + 人工干预成本 + 返工成本 + 失败风险”理解单位任务成本。该公式是分析框架，不是已有测算结果。评估时至少记录：

- 任务类别与复杂度；
- 使用工具及实际账单/套餐成本；
- 人工介入时间；
- 返工轮数；
- 是否通过预先约定的验收标准。

在拿到一轮真实交付数据之前，不固化模型占比或成本结论。
