# 产品方向与工作台需求

> 来源：ChatGPT 对话「DAEN 域联」。下文把用户表达与助手建议分开；建议项不代表已确认决策。

## 用户明确表达

### NiuMa 的体验

- NiuMa 能用，但不太好用。
- 已指出三项问题：文档不能直接打开；图片不能上传和识别；切换项目比较麻烦。
- 最有优势的体验是写代码过程不枯燥：界面里多个 AI Agent 持续有动作，像办公室里的团队。
- 用户认可增加办公室氛围感，并提出把办公室放大后投屏到大屏幕。
- 大屏希望能看到谁在做什么；未来触屏时可点击 Agent 查看其功能和操作。
- 核心画面是 Agent 与人类成员共处在一个虚拟办公室。

### 工具与成本背景

- 主要开发工具提到 Trae 与 DeepSeek。
- 用户说明 Trae 是包月，月费固定；DeepSeek 按量充值。
- 用户提出从经济角度看，使用 Trae 有降低成本的作用。

## 产品需求归纳

以下是从上述反馈归纳出的需求，不代表实现方案已经确定：

1. **办公室大屏**：清晰展示项目、成员/Agent、正在处理的任务、当前阶段和阻塞。
2. **可观察的工作状态**：把真实任务事件呈现为 Agent 的工作状态；状态应能追溯到任务或产出，避免只有装饰动画。
3. **触屏详情**：点击成员或 Agent 后可查看角色、项目、当前任务、状态、最近活动、产出和阻塞；可执行操作需再定义权限与确认机制。
4. **人机共处**：人类成员和 Agent 都是办公室中的成员，并能显示在线、开会、等待确认等状态（具体状态是设计建议）。
5. **基础工作台易用性**：文档可直接查看、图片可上传识别、项目可快速切换。

## 对话中的助手建议（待确认）

- 将 NiuMa 保留为 Agent 编排引擎，另建统一 Workspace 处理项目、文件、图片、对话和状态。
- 把产品称为「虚拟智能办公室 / Virtual AI Office」或「AI Development Office」。名称和定位尚未确认。
- 将界面拆为 Office Wall（展示）、Interactive Office（触屏交互）、Control Console（工作控制台）。
- 以项目墙、Agent/成员、任务流转、可点击产出物和会议室构成办公室空间。
- 采用分阶段路线：先验证状态看板与投屏，再加触屏和项目文件交互，之后才考虑沉浸式空间。

## NiuMa 方向的讨论状态

对话先出现过“以 NiuMa 为唯一主体”的肯定回答；随后用户补充文档、图片和项目切换问题，助手把建议修订为“保留 NiuMa 作为候选编排内核，主工作台体验需要补足”。因此不能把“最终平台选择已定”当作稳定结论。办公室氛围是用户明确认可的产品方向；是否继续以 NiuMa 为主体仍需结合代码评估和实际流程验证。

- 大屏首版必须显示哪些真实数据？数据从哪个任务/Agent 系统读取？
- 点击 Agent 后首版允许查看和执行哪些操作？哪些操作需要人类确认？
