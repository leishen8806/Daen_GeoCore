> VALIDATION FIXTURE — NOT A SPECIFICATION, NOT A DATABASE SCHEMA, NOT AN API CONTRACT.

This matrix guides the independent Reviewer. It does not create new Domain Model rules.

|---|---|---|
| Same Place | A, G | Does the frozen locus-based definition support this identity judgment? |
| Merge | G | Does the action follow frozen merge semantics? Was survivor policy invented? |
| Split | H | Is this mis-conflation or true division under the frozen case definition? |
| Access Point | D, E | Is the object genuinely an Access Point rather than business pickup/drop-off semantics? |
| Current DAEN Representation | B, C, F, I | Is uncertainty preserved? Is selection being mistaken for absolute truth? |
| Business boundary | B, J | Was any business entity, policy or verdict required? |
| Fundamental concept | A–J | Did execution require an object absent from the nine frozen concepts? |
| Provenance and Quality | B, C, F, I | Are attribution and uncertainty meaningful and preserved? |
| Maintenance friction | A–J | Did field verification, specialist judgment, repeated research or multiple actions create an operational warning? |

The Reviewer records PASS / FAIL / INEXPRESSIBLE only after execution and manual review. Checker output cannot replace this matrix.
